# General ledger and Financials

The ledger import, and every report built on it: the Financials pivot, Financial Ratios, Income Statement, Chart of Accounts and Reconciliation — plus the Balance Sheet, which comes from QuickBooks directly rather than from the imported ledger. Budget and Cost of Benefits read the same ledger and have their own pages.

Code: `syncGeneralLedger` in `src/lib/quickbooks.ts`, `src/lib/financials.ts`, `src/lib/pivotServer.ts`, `src/lib/statementServer.ts`, `src/lib/reconciliation.ts`, `src/app/(app)/financials/`.

- `syncGeneralLedger` imports the chart of accounts (`gl_accounts`) and every posted ledger line (`gl_lines`) via the QBO GeneralLedger *report* API (quarter-sized windows since `FINANCIALS_START_DATE`, currently `2025-01-01`, defined in `src/lib/businessRules.ts` — read the warning there before changing it), so QuickBooks does the double-entry expansion — never reconstruct postings from raw entities.
- The Reports API caps a response at 400,000 cells and signals overflow only by cutting the report short (an "Unable to display more data" row) — and since the report runs in chart order, the cut silently drops the last accounts (other income/expense, e.g. interest).
- `parseGlReport` flags that, and `fetchGeneralLedgerLines` halves any truncated window until each piece fits; never ingest a report without that check.
- A fetched ledger is also checked before anything is written (`assertLedgerPublishable`): the sync refuses to publish — leaving the previous ledger in place and failing the step — when some report windows came back without class/customer/vendor columns and others with them (the 400 fallback to `GL_COLUMNS_MINIMAL` is retried once and counted, never silent), when no window has classes but the published ledger does, or when the line count is under half the published generation's; `parseGlReport` throws if the amount column is missing.
- `QB_LEDGER_FORCE_PUBLISH=1` overrides the refusals once the change is confirmed real in QuickBooks.
- Pre-2025 ledger lines are frozen audited history: migration `0020` marks them `archived`, `gl_line_facts` shows them outside the sync's generation scheme, and `prune_gl_lines` skips them, so syncs can't drop or duplicate them.
- Amounts are natural-signed (positive increases an account in its normal direction).
- **Every Financials report (pivot, Income Statement, Ratios, Reconciliation, Budget) shows the ledger as booked so it ties to QuickBooks: no intercompany eliminations below Net income (intercompany activity is handled on the balance sheet, so that income is only counted once) and no allocations between categories (the Employee Benefits → Direct Costs reclassification was removed; a replacement approach is planned).** The Financials page (`src/app/(app)/financials/`) slices them through the `gl_pivot` SQL function (migration `0009`); aggregation stays in Postgres.
- **Every ledger pivot is read through `loadPivotCells` (`src/lib/pivotServer.ts`)**, which calls `gl_pivot_cells` (migration `0042`): the whole pivot as one JSON value, so a page view scans the date window once. Reading `gl_pivot` directly goes through the API's 1000-row pages and re-runs the aggregation per page. `gl_pivot` and `gl_lines_detail` filter by org (`0042`) so `gl_lines_date_idx` range-scans the window — any new ledger read must do the same.
- Cell drill-downs list raw lines via `gl_lines_detail` (migration `0010`), whose dimension CASE expressions must stay in lockstep with `gl_pivot`; shared dimension/scope vocabulary lives in `src/lib/financials.ts`.
- GL data is admin-only: the Financials pages/export verify the caller with `requireAdmin()` and then read via the service-role client — RLS on `gl_accounts`/`gl_lines`/`gl_sync_state` checks `is_admin()` (migrations `0014`/`0015`) to block direct API access, but its qual makes `gl_pivot`-sized queries blow the statement timeout, so the app's own read path bypasses it after the role check.
- The Chart of Accounts page (`/financials/accounts`) assigns a user-owned `category` per account (migration `0019` — the sync upsert's column list never touches it); its *Refresh from QuickBooks* button (`refreshChartOfAccounts` → `syncChartOfAccounts`, sharing `upsertChartOfAccounts` with the ledger sync) pulls the chart only — no ledger lines, nothing deleted — and lands on the *New accounts* view (`?new=1`, accounts whose `created_at` is within `NEW_ACCOUNT_DAYS`, so nightly-sync additions show too).
- The category is what the expandable Income Statement (`/financials/statement`, assembled by `buildCategoryStatement` in `src/lib/financials.ts`) uses to group Revenue/Expense accounts.
- **EBITDA** sits below Net income on the Income Statement and its export: Net income plus four add-back lines (Interest, Income taxes, Depreciation, Amortization), each expandable to its expense accounts. Which accounts count is a setting (`ebitda_add_backs`, Settings → Business rules), applied by `ebitdaAddBackMatcher` in `src/lib/financials.ts`: an account number listed under an add-back (or under *Never add back*) decides first — the account's own number, then each parent's, so sub-accounts follow their parent unless listed themselves; otherwise, while *Find add-backs automatically* is on (the default), `ebitdaAddBackKind` picks by QuickBooks detail type (`gl_accounts.account_sub_type`), then by account name when the detail type is generic. Only Expense-classified accounts qualify (interest income is not netted), and the automatic search excludes QuickBooks' "Taxes Paid" detail type on purpose: payroll, property and sales taxes are operating costs. Add-backs are the accounts' own booked amounts, so each ties to its row above; nothing is reclassified and Net income is unchanged. The Budget page shares the statement table but passes no add-backs, so it shows no EBITDA.
- The Income Statement shows one QuickBooks class at a time from a Class dropdown (`?class=`, default All classes; months are the default columns and classes are never columns): it and its export read account × month × class cells through `loadStatement` in `src/lib/statementServer.ts` (via `budget_ledger_summary`), so All classes is exactly the sum of the classes.
- The Reconciliation page (`/financials/reconciliation`) verifies the imported ledger ties to QuickBooks: upload the consolidated P&L Excel export (monthly columns) and `src/lib/reconciliation.ts` parses it (`parsePlWorkbook`), truncates it at the last complete month (`omitMonthsAfter` — the in-progress month is omitted across all Financials views and never enters the tie-out), and diffs it account × month against `gl_pivot` cells (`buildReconciliation`) — both sides natural-signed, so amounts compare with no sign flipping.
- The tie-out is per **detail account**, never by the app's categories or by parent rollups: the parser rebuilds each export row's full "Parent:Sub" path from QuickBooks' header / "Total for …" group pairs (only QB's own statement sections are sections) and matches it to `gl_accounts.fully_qualified_name`, falling back to the account's own name only when that name is unique among the unmatched rows on both sides; an export with sub-accounts collapsed is flagged with a warning.
- Neither side is adjusted, so every account and net income should tie to the cent.
- The page action and the Excel export (`/api/export/reconciliation`, a POST that re-uploads the same file) share the file → result pipeline in `src/lib/reconcileServer.ts`.

## Balance Sheet

Code: `src/lib/balanceSheet.ts` (parsing, merging companies, calendar rules), `src/lib/balanceSheetServer.ts` (loader and param parser shared by the page and its export), `syncBalanceSheet` in `src/lib/quickbooks.ts`, `src/app/(app)/financials/balance-sheet/`, `src/app/api/export/balance-sheet/`.

- **The Balance Sheet is never summed from `gl_lines`.** The imported ledger starts at the import window and carries no opening balances, so balances built from it would be short by everything posted earlier. `syncBalanceSheet` pulls each company's own QuickBooks BalanceSheet report (accrual, the same basis as the ledger import) as of a month end and stores the parsed tree in `balance_sheet_snapshots` (migration `0043`), one row per company per month end.
- `parseBalanceSheetReport` checks a report before it is stored: it must be for the date asked for, have both halves, and balance to the cent. One that fails throws, so the step fails and the previous snapshot stays.
- **The page shows the prior month end** (`priorMonthEnd` of today's date in `QB_SYNC_TIMEZONE`), so it moves to the month just closed at midnight on the last day of each month. Earlier month ends stay available from the As of dropdown (`?asOf=`), as they were last pulled.
- **Two things refresh it, both through the sync queue** (see [quickbooks-sync.md](quickbooks-sync.md)): a `month_end` run the cron worker starts in the first hours of the 1st (`isMonthRollover`), and a `balance_sheet` step per company in every nightly run, which re-pulls the same month end so entries posted to it during the close show up the next morning. The page's *Refresh from QuickBooks* button does the same pull as a manual run.
- With several companies each is a column, lines matched by name within their section (`mergeBalanceSheets`), and Combined is their plain sum — no intercompany eliminations, like every other report here.
- Admin-only, like the ledger: `requireAdmin()` then the service-role client; RLS on the table lets only admins read it and no API role write it.

## Financial Ratios

Code: `src/app/(app)/financials/ratios/`, `buildIncomeStatement` in `src/lib/financials.ts`, `src/lib/balanceRatios.ts` (figures and ratio math), `src/lib/balanceRatiosServer.ts` (loader).

- The page has two sources. **Profitability** (margins as a percent of revenue) reads the ledger through `loadPivotCells`, like the Financials pivot. **Liquidity, leverage and returns** read `balance_sheet_snapshots` — never the ledger, for the reason given under Balance Sheet.
- Balance sheet figures are QuickBooks' own section totals (`balanceFigures` finds Current Assets, Bank Accounts, Accounts Receivable, Current Liabilities, Liabilities and Equity by QuickBooks' group name, falling back to the label), so each ties to the Balance Sheet page for the same month end. Nothing is re-summed from accounts.
- The balance sheet table has one column per month end in the period that has a snapshot and follows the Company filter only (All companies = the Balance Sheet's Combined, a plain sum with no eliminations); the Columns control applies to the profitability table alone.
- Return on assets, return on equity and days sales outstanding (`returnRatios`) set the period's income against the balance sheet at the period end, and are shown only when that month end has a snapshot. Net income is restated to an annual rate (× 12 ÷ months); balances are period-end, not averaged.
- A ratio over a zero or negative base (no current liabilities, negative equity) is null and shows a dash rather than a misleading number.
- Before migration `0043` is applied the balance sheet half shows a message naming it; the profitability half still works.
