# Budget

`/financials/budget`. Code: `src/lib/budget.ts`, `src/lib/budgetServer.ts`, `src/lib/budgetWorkbook.ts`, `src/app/(app)/financials/budget/`, `src/app/api/export/budget*/`.

- `/financials/budget` (admin-only, sidebar Budget and Forecast → Budget) is a calendar-year budget (the `budgetYear` setting — Settings → Business rules, default 2027 in `src/lib/appSettings.ts`; the page, exports and manual each read it with `loadAppSettings`, and growth rates, typed figures and initiatives are all keyed by year) in the Income Statement's layout.
- Baseline = each account's actuals for the twelve months ending June 30 of the prior year (`baselineRange`), read in one ledger scan by `budget_ledger_summary` (migration `0027`, one JSON row — paged `gl_pivot` calls per company timed the page out; `0034` adds each cell's QuickBooks class as a seventh tuple element; `0035` scopes it to the org so `gl_lines_date_idx` range-scans just the window instead of the whole ledger — any new ledger read must do the same) and mapped month-for-month onto the budget year — except **December, which takes November's baseline amounts** (`decemberFromNovember`, applied once in `loadBudget`, because year-end adjusting entries are always booked in December; actuals in Budget vs Actual stay as booked) — then grown by per-company growth assumptions: each account at its own company's rate for its `gl_accounts.category` (`budget_category_assumptions`, migration `0028`, keyed by classification + category label), falling back to the company's revenue / expense default (`budget_assumptions`, migration `0026`; direct costs use the expense default) for categories with no rate and for uncategorized accounts.
- Growth looks categories up in each realm's own account map (`realmCategories`), not the consolidated display map.
- `save_budget_assumptions` writes a company's defaults and its whole category set in one transaction (service-role only).
- New initiatives (`budget_initiatives` + `budget_initiative_lines`) carry expected amounts per account for the budget year, spread evenly from a start month through an end month (`end_month`, migration `0029`; `spreadInitiativeLine` is the one spread both the budget and the exports use); they fold into the budget **only when `status = 'approved'`** — proposed/rejected ones are listed but excluded, and guard triggers lock an initiative's lines and its start/end months unless it is proposed.
- Saving an initiative replaces its lines in one transaction (`replace_budget_initiative_lines`, migration `0039`, service-role only).
- Initiatives export by month via `/api/export/budget-initiatives` (`?id=` one initiative, else `?company=` all in view; initiative tables only, no ledger read) and as the budget workbook's *Initiatives by month* sheet — both written by `writeInitiativesByMonth` in `src/lib/budgetInitiativeSheet.ts`.
- An admin can also type figures straight into the budget statement's account cells (single company, Budget view): a month, or an account's annual Total, which `respreadTotal` re-spreads in the months' current shape.
- Each typed month is a row in `budget_account_overrides` (migration `0031`, keyed by account full name × class × month since `0034`; `set_budget_account_overrides` replaces one account × class's set, service-role only) that replaces that account-class-month's growth-based amount in `accountBaseMonths` / `growBaselineCells` — growth edits no longer move it, and approved initiatives still add on top.
- Typed figures autosave per cell (`saveAccountOverrides`), so the export reads the saved set (plus a *Typed figures* sheet); `StatementTable` takes an optional `editor` for this and is otherwise unchanged on the Income Statement.
- The growth % fields are plain text (no spinner arrows).
- **The budget is built per QuickBooks class and rolls up** (migration `0034`): every baseline cell (`BudgetCell` = `PivotCell` + `class_name`), typed figure, and initiative (`budget_initiatives.class_name`, locked like its months unless proposed) carries a class keyed exactly as `gl_pivot` keys its class dimension (`NO_CLASS` = `'(no class)'`), `assembleBudget` takes a `cls` filter (null = All classes), and a company's budget is the sum of its classes and All companies the sum of the companies — never computed separately.
- Growth rates stay per company and apply to every class.
- The page's Class filter (`?class=`) scopes the statement, tiles, initiatives, and exports; typing needs one company and one class (or a company with a single class).
- On All classes the page sends the browser cells merged across classes (`mergeClasses`; accounts with typed figures stay split), so the default view costs no more than before classes.
- A failed load renders as a banner via `budgetLoadErrorMessage` (e.g. a missing migration), not a 500.
- `0034` split pre-existing whole-account typed figures across each account-month's baseline classes pro-rata, so no total moved.
- `src/lib/budget.ts` re-keys everything into synthetic `PivotCell`s so `buildCategoryStatement` assembles the budget exactly like the statement; Budget vs Actual feeds full-year budget, YTD budget, and YTD actual as three columns of one statement.
- The page (`BudgetWorkspace`, client-side so growth edits re-price live; nothing is stored until Save changes) and the Excel export (`/api/export/budget`, which carries the on-screen rates as `growth=<realm>:<rev>:<exp>` and `cgrowth=<realm>:<R|E>:<pct>:<category>` params — `budgetExportHref` / `assumptionsFromParams` own that format; on All companies it writes the consolidated tab then one tab per company, each assembled like that company's own view — its categories) share the server loader `loadBudget` in `src/lib/budgetServer.ts` and the assembly `assembleBudget` in `src/lib/budget.ts`, so the file always matches the screen.
- The workbook itself is written by `buildBudgetWorkbook` in `src/lib/budgetWorkbook.ts` (request parsing + admin check in `budgetExportContext`), shared by `/api/export/budget` and `/api/export/budget-classes` (a zip of one workbook per class, for distributing class budgets); a single company on All classes gets one tab per class after the company tab.
- On All companies the page's *Export a company…* picker downloads one company's standalone workbook — the same route with `company=<realm>` and only that company's on-screen rates — whose statement is identical to that company's tab in the All companies workbook; on All classes *Export a class…* downloads one class's workbook (`class=<class>`) or the per-class zip.
- Files are named after the company and class.
